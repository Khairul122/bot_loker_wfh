# Audit 001, 2026-10-10

Mode: AFTER. Read-only audit. No source fix applied.

## HIGH

### 1. Settings panel builds malformed DOM
- File: `src/bot_loker_wfh/office/js/ui/settings.js:95-120, 240-252, 362-369`
- Evidence: helper `el(tag, cls, text)` accepts three arguments, but code passes object/children arguments such as `el('div', 'settings-section', { id: ... }, [...])`, `el('div', { id: 'skills-list', ... }, '...')`, and arrays as `text`.
- Result: attributes are not assigned, child controls become text or disappear, `#skills-list` is not created, and hidden 9Router sections cannot be toggled reliably.
- Impact: core Settings tabs render incorrectly or unusably.
- Fix direction: use `el` only with its real signature, then assign `id`/`style` and append children explicitly; add DOM smoke test.
- Rule: R-26, R-27, C-2.

### 2. Settings action buttons use POST while server implements GET
- Files: `src/bot_loker_wfh/office/js/ui/settings.js:137-145, 177-185, 224-233, 380-389`; `src/bot_loker_wfh/office_server.py:275-289, 297-381`
- Evidence: browser probe returned `404` for POST `/llm/list-models`, `/browser/test`, `/ats/list`, and `/form/test`; GET routes return `200`.
- Result: model list, BrowserMCP test, ATS list, and Form Engine test buttons fail. POST `/llm/test` also caused connection failure during live probe because its operation is synchronous and expensive.
- Impact: multiple visible controls are dead or unreliable.
- Fix direction: make read/test endpoints consistently GET and call `fetch` GET, or add explicit POST handlers with bounded request behavior. Keep one method per endpoint.
- Rule: R-26, R-35.

### 3. API secrets exposed to browser and returned in JSON
- File: `src/bot_loker_wfh/office_server.py:64-112, 273-289`
- Evidence: `/settings.json` returns `anthropic_api_key` and `ninerouter_api_key` directly. Localhost-only binding reduces exposure but does not protect other local processes, browser extensions, or a compromised local page.
- Impact: API credentials can be read through DevTools or any same-browser local request.
- Fix direction: return masked booleans/last-four only; never send secret values to UI. Preserve existing secret when an empty value is submitted.
- Rule: security review, R-36.

### 4. Settings endpoint accepts arbitrary keys and writes them to `.env`
- File: `src/bot_loker_wfh/office_server.py:321-341`
- Evidence: `key` is taken from request JSON, unknown keys bypass DB validation, then `save_dotenv({key: value})` writes them. No allowlist or key syntax validation exists.
- Impact: browser-side bugs or local request forgery can corrupt runtime configuration, create unexpected environment variables, or persist attacker-controlled values.
- Fix direction: whitelist supported settings, validate type/range/format per key, reject unknown keys with `400`, and separate secret update handling.
- Rule: security review, R-26.

## MEDIUM

### 5. Skills and modal output render untrusted data with `innerHTML`
- File: `src/bot_loker_wfh/office/js/ui/settings.js:318-327, 504-536, 548-567`
- Evidence: OpenCode skill names, descriptions, tags, model names, ATS fields, and error text are interpolated into HTML without escaping.
- Impact: injected markup from external command output or remote model/ATS data executes in the local office page.
- Fix direction: build nodes with `textContent`; if HTML is unavoidable, escape every interpolated value and keep a strict CSP.
- Rule: security review, R-25, R-38.

### 6. Form test uses stale engine value
- File: `src/bot_loker_wfh/office/js/ui/settings.js:337-346, 379-384`
- Evidence: callback sends `s.form_engine`, where `s` is captured during panel render. Changing the select does not update `s`.
- Result: selecting BrowserMCP then clicking Test still tests old engine, commonly Playwright.
- Fix direction: read `$('form_engine').value` inside click handler.
- Rule: R-26.

### 7. Settings panel overflows mobile viewport
- Files: `src/bot_loker_wfh/office/css/office.css:198-209`; `src/bot_loker_wfh/office/index.html:5`
- Evidence: panel has fixed `width:420px`; mobile media query has no settings override. At 375px viewport, `right:14px` leaves panel wider than screen. `maximum-scale=1` also prevents user zoom.
- Impact: controls clip or create horizontal overflow; low-vision users cannot zoom.
- Fix direction: `width:min(420px, calc(100vw - 16px))`, mobile left/right inset, and remove `maximum-scale=1`.
- Rule: R-03, R-32.

### 8. Modal dialogs cannot close with Escape and lack dialog semantics
- File: `src/bot_loker_wfh/office/js/ui/settings.js:499-573`
- Evidence: close behavior exists only for close button and backdrop click; no Escape listener, `role="dialog"`, `aria-modal`, or focus handling.
- Impact: keyboard users can get trapped in modal workflow.
- Fix direction: add dialog semantics, Escape close, and focus return to triggering button.
- Rule: R-32.

### 9. Policy list displays literal HTML tags
- File: `src/bot_loker_wfh/office/js/ui/settings.js:362-369`
- Evidence: `el(..., text)` assigns `textContent`, but code supplies `'<li>...</li>'` string.
- Result: user sees raw `<li>` markup instead of a list.
- Fix direction: create `li` nodes and append them, or use `innerHTML` only with static trusted strings.
- Rule: R-26, R-27.

### 11. BrowserMCP/LLM test routes block request threads
- File: `src/bot_loker_wfh/office_server.py:447-515, 573-599`
- Evidence: GET `/browser/test` timed out in live probe while starting external process and waiting up to 15 seconds. LLM test performs network calls synchronously.
- Impact: ThreadingHTTPServer can accumulate blocked worker threads and UI shows no progress state beyond request timeout.
- Fix direction: bounded subprocess/network timeouts, explicit progress/error response, and avoid long tests in request handler.
